# GLM 用量 + ZCode 上下文洞察（glm-usage）

智谱 GLM Coding Plan（Max/Pro/Lite）与 ZCode 免费套餐的本地用量看板，加上对标
[dsh-context](https://github.com/bowenliang123/dsh-context)（DeepSeek Harness 插件）的
**ZCode 本地会话上下文洞察**，含 ZCode 应用内面板插件。

## 功能

### v2.9.1 系统健康度数据修复

- 「今天 / 7 天 / 30 天」按本地自然日统计。官方数据按日期和本机解码速度对齐，当天没有样本时图上保留空缺。
- Max / Pro 和 Lite 各自显示最近的有效官方测速及日期。选「今天」时若快照尚未发布，摘要会标注最近官方成绩的日期，图表仍展示当天。
- 区分官方未发布样本、鉴权失败和连接失败。本机有采样时可继续查看实际解码速率与样本数。
- 此版包含 v2.9.0 的历史请求、日期筛选、活动回执与 Agent 联动。

### v2.9.0 历史请求与跨页联动

- 在请求趋势点击固定步骤，悬浮其他步骤预览，移开恢复。左右方向键切换，按轮查看长会话。右栏可查更早日志，并与上一个可读快照比较分类 Token。
- 步骤关联会区分标识匹配、同轮模型与时间及输入输出用量对应、待选候选、缺少记录。请求正文按原始位置和内容指纹校验。单条超过 24 MiB 的日志可能无法读取。
- 七天柱图与热力图共用本地日期筛选。排行名称筛选会话，行末「明细」打开执行记录。命令和技能按记录日期统计，执行回执按会话与调用 ID 关联。搜索上下文时可在当前结果内翻页。
- 固定 Agent 成员可同时查看其收发的协作记录、待办以及按时间排列的事件。协作时间线中的待办记录使用最近更新时间。
- 混合模型的预估费用分别计价，缺价时显示覆盖数。用量页重开后恢复暂停设置。分类、DNA、矩形图和额度卡继续使用原有布局。

### v2.8.6 多账号套餐与待生效权益

- 套餐卡按凭据合并多账号数据：ZCode 按提供方家族分账号，`billing/balance` 只返回凭据所属账号的记录——现在逐个凭据查询后按 id 去重合并，bigmodel 侧的 Start Plan 叠加包（如 ZCODE GLOBAL BUILD）不再因凭据家族不匹配而缺失。
- 待生效权益可见：套餐已开始但权益 `effective_at` 未到（如领取后 23:00 发放）时，卡片显示「待生效」徽标与权益摘要（模型 · 额度 · 生效时间 · 有效期）；配额落账后自动切回常规用量条。
- 修复下拉菜单展开时浮动提示框遮挡选项的问题（提示框在菜单展开期间不再弹出，菜单层级提至最高页内层）。

### v2.8.5 缓存计价与刷新控制

- 费用估算引入缓存价：价格口径升级为 `[输入, 输出, 缓存读?, 缓存写?]`（¥/百万 tokens），费用 = 纯输入×输入价 + 输出×输出价 + 缓存读×缓存读价 + 缓存写×缓存写价，未配置缓存价时该部分按输入价估算。内置目录收录 GLM（bigmodel 官方缓存命中价）、DeepSeek、OpenAI、Anthropic 官方缓存价；LiteLLM / OpenRouter 同步目录一并提取缓存价字段；价格编辑与手动添加补缓存读/写输入框；存量已计价模型提供一键「补缓存价」（保留原输入/输出价，仅补入目录缓存价）。
- 用量页自动刷新频率新增「停止刷新」：暂停定时拉取（倒计时与副标题明示状态，重启面板后保持），手动刷新不受影响；`set_refresh` 支持 0（暂停）。
- 刷新按钮改为纯图标药丸按钮（与主题按钮同几何）：SVG 图标随刷新平滑旋转（手动与自动刷新均有反馈，最短 600ms 保证可感知），悬停微转提示可点，不再占用文字。

### v2.8.4 加载体验与模型价格管理

- 光带骨架屏：四个标签页全部区块在数据到达前按最终布局同构占位（复用真实内容 class/网格，骨架与数据同尺寸），光带斜向扫过、有限次后自动静止；数据落位原位替换——首载不重排、不闪烁，会话切换同样无跳版。
- 模型价格管理（洞察 · 预估费用入口）：内置 GLM / DeepSeek / GPT / Claude 官方线参考价，一键同步 LiteLLM 社区目录（实测 2,045 条）与 OpenRouter 直连/中转价（356 条），本地模型自动匹配推荐（置信度排序，官方线优先）并支持单条 / 批量应用、备选切换、手动定价与覆盖；USD→CNY 汇率可调，价格仅存本地 config。
- 系统健康度新增「实际 · 本地」解码速率（输出 tokens ÷ 解码时长，与洞察 tps 同口径）：绿色实线 + 基线渐变填充，与官方理论线同图对比；十字游标交互（垂线 + 交点数值）取代浮动提示；官方快照不可用时仅展示本地序列。
- 使用详情柱状图与洞察日图风格统一：外端圆角、疏朗间距、实色渲染与悬浮提亮。
### v2.8.3 轮询与载荷优化

- 网页登录令牌进程内缓存（成功 10 分钟 / 失败 60 秒，上游鉴权拒绝时自动失效重读）：未配置 API Key 时不再每个刷新周期整库拷贝内嵌浏览器 Cookie 库并另起 sqlite3 子进程。
- 配额历史采样抽取为独立模块 `history.mjs`：采样值未变跳过写盘（原每周期必重写 history.json）；读取按 mtime+size 指纹缓存并返回防御性拷贝（原一次轮询完整解析 3 遍，48h 窗口封顶约 600KB）。
- 走势序列服务端等距封顶 180 点（面板 sparkline 仅消费 90 点；首尾保留、时间范围不变），配额轮询载荷实测 94KB → 19KB。
- model-io 读取缓存去掉 4s TTL：size+mtime 指纹即失效信号（追加写入必然推进 mtime），上下文页轮询不再对未变化文件周期性重读尾部并重新解析（~20ms → ~6ms）。
- 活动明细命令截断 8000 → 2000 字符：单条命令实测可达 8.5KB，原上限下 500 行最坏 4MB 载荷。
- 视图状态保存防抖 600ms（原搜索框每键一次 RPC + 原子写盘），页面隐藏 / 关闭时立即冲刷，不丢最后一段输入。
- 测试 34 → 38：新增历史采样跳写 / 48h 裁剪 / 采样间隔下限 / 点列封顶四组用例。

### v2.8.2 数据层性能优化

- 命令 / 技能统计改为按天分桶的增量物化（`~/.glm-usage/activity-cache.json`，含 schema 版本与 part 行 rowid 水位线）：首次全量扫描后每次刷新只扫新增行，分桶常驻内存、水位推进时原子替换写盘；缓存缺失 / 损坏 / 版本不符 / 水位回退（库被 VACUUM 重建）时自动全量重建，任何读写异常自动回退原直查路径。口径说明：桶只增不减，会话删除后 all 范围统计可能轻微高估（近似口径）。30 天洞察实测由 ~140ms 降到 ~19ms。
- Agent 编队成员聚合批量化：每成员 2 条用量查询合并为整个家族 2 条 IN 查询（按 MAX(started_at) 分组后 JOIN 回取最近模型，不依赖窗口函数），成员数增长时不再线性放大查询数。
- model-io 尾读反向分块：从文件末尾按 256KB 步长向前读块（凑不齐时 ×4 扩块），在已读窗口内自后向前找完整行，凑齐所需条数即停；常态单次读取由 24MB / 8MB 降到 1MB 量级，单行超块或找不到完整行时仍能回退到与旧实现一致的大读上限，缓存键 / TTL / LRU 与返回语义不变。
- get_activity 明细改为两段式查询：先按索引取最近 500 条工具执行，再仅对这批会话与时间窗批量补齐命令 / 文件 / 技能明细，30 天范围耗时由约 1.6 秒降到 0.2 秒内。
- model-io 读取缓存引入 LRU 淘汰（最多 8 条、估算 64MB，TTL 不变），长会话遍历不再累积内存。
- 洞察 daily 与 daily7 合并为一次按天聚合，daily / daily7 / heatmap 不再返回 session_ids 明细（按天取会话列表改用新增的 get_day_sessions），响应显著变小。
- 命令 / 技能单击筛选（pick）同样改走物化日分桶（单日单键 400 会话上限、聚合 4000 总量界与原直查截断口径一致），30 天实测约 400ms 降至 1ms 内；物化框架重构为可注册的增量扫描（ACTIVITY_STORES / ACTIVITY_SCANS），新增 part 维度统计只需注册一条扫描并升缓存版本号。
- 会话卡构成的尾读上限由 8MB 对齐 24MB：单条请求超过 8MB 的超长会话卡片不再恒为空（反向分块保证常态读取量不变，仅在真需要时多读）。

### v2.8.1 用量图费用轴（对齐 dsh-context）

- 近 7 天用量改为每天 Token 与费用双柱并排：Token 柱保留缓存/输入/输出三段构成并精简命名，柱顶显示当日总量；卡片固定展示最近 7 天，不随今天 / 近 7 天 / 近 30 天范围筛选变化（服务端固定返回 daily7 序列，对齐 dsh-context）。
- 新增右侧费用坐标轴（5 档，顶档为范围内实际最大费用）；未配置 `prices` 时以 ¥— 占位，位置保留。
- 图例改为「Token（缓存/输入/输出）」与「费用（仅含支持计价映射的模型）」；未计价模型不计入当日费用，也不会把当日清零。
- 副标题在有计价数据时附费用合计；预估费用 KPI 口径不变（范围内全部模型计价才显示）。
- 活跃度卡对齐 dsh：副标题改为「按日期筛选」，新增 会话 / Token 双指标切换；热力图改为周日对齐的 8 周列布局，带星期一/三/五行标、跨月列月份标签、离散 5 级色阶与未来日期占位。
- 洞察四卡对齐 dsh：以「技能加载」卡（Skill 工具调用计数与技能名排行，明细弹窗 get_activity 新增 skills 类型）替换「文件活动」（文件数据仍可经 get_activity kind=files 获取）；工具 / 命令 / 技能排行行改为 dsh 同款——色点 + 完整名称 + ×次数，进度条移到名称下方的行底 2px 彩条。
- 会话列表新增数字页码分页（‹ 1 … 4 5 6 … N › + 页码信息，每页 12 个）：筛选 / 排序变化回第一页，新选中会话自动跳到所在页，背景刷新保持当前页，页码随视图持久化；对比 dsh 仅前后页的翻页更适合长会话管理。
- 用量柱状图取消点击选中效果，悬浮即显示精简数据浮窗（日期 · Token、缓存 / 输入 / 输出、费用），按日筛选收敛到活跃度热力图。
- 启动直达恢复的标签页：首帧不再渲染默认用量页再跳转——标签内容、高亮与右上角刷新控件在视图恢复完成后一次性显示（刷新 / 重开面板不再从用量页闪跳）；桥接 2.5 秒未就绪时兜底显示默认用量页。
- 刷新频率新增 3 秒 / 5 秒档位（set_refresh 下限放宽至 3~600 秒）；下拉触发器箭头改为几何居中的 CSS 箭头并收紧宽度；主题按钮重绘为太阳 / 月亮双图标，切换时带旋转形变过渡（减少动态偏好下禁用）。
- Agent 编队递归纳入全部下级派生代理：side chat 等子代理再派出的代理按真实层级嵌套挂在其父卡片下方（纵向思维导树布局，肘形连线沿左轨下垂），家族汇总（会话 / 近期活跃 / 待办 / 模型请求）、连线与悬浮高亮均覆盖全家族，成员明细按层级缩进。
- 编队页新增「跨 Agent 协作」与「协作任务」卡：Agent 派发（含 agentId → 子会话精确关联）与消息记录按时间排列、类型筛选，悬浮 / 点击定位对应代理；全家族待办按 运行中 / 待处理 / 已完成 分相筛选；代理卡片显示运行状态。

### v2.8.0 视图持久化

- 筛选、当前页面和会话选择保存到本机 `~/.glm-usage/views.json`（权限 600），关闭面板、重启应用后恢复。

- 失败或执行中的请求未上报输入时不参与增量计算；下一次有效请求与上一有效请求比较，防止误报压缩。
- 命令执行总数独立于前 12 个程序排行，长会话不再少计。
- 复制反馈显示在当前原生弹窗内部，避免被 ZCode 的 dialog 顶层遮挡。
- 30 天用量图的日期标签保持单行居中，避免窄柱位导致日期换行。

### v2.5 交互与 ZCode 适配

以 [dsh-context v0.84.1](https://github.com/bowenliang123/dsh-context/releases/tag/v0.84.1)
的源码和视觉结构为参照，重做交互状态与数据联动：

- **环形图**：图例与扇区双向高亮，中心数值跟随悬浮，点击固定，Esc 取消。
- **上下文工作区**：左侧构成与趋势，右侧浏览器；分类条、图例、分类行、DNA 分布条保持同一套颜色与高亮语义。
- **浏览器**：分类、按请求顺序排列的 DNA、按估算 Token 分配的矩形图；搜索、展开、增量显示、最新/上一请求切换；条目支持按需读取内容、前后导航与复制。
- **请求趋势**：总量/带正负号的输入增量、完整柱位命中区、悬浮提示、固定选择、方向键导航；事件点击定位最近请求。
- **活动明细**：工具、命令、文件排行可打开明细；汇总格切换全部/失败/后台/超过 5 秒，支持搜索、程序筛选、排序和返回所属会话。只读展示，不执行历史命令。
- **会话与 Agent**：归档、关键词、日期、完整目录分组筛选；Agent 连线随实际布局重算，节点与成员行双向高亮，可进入对应上下文。
- **稳定刷新**：保留展开、搜索、焦点、滚动和已选请求；丢弃迟到响应，避免快速切换会话或时间范围后串数据。
- **可访问性**：键盘操作、明确焦点、提示框避让视口、明暗主题、窄窗口、减少动态偏好。

GLM 的 OpenAI / Anthropic 兼容请求均可解析。输入总量以模型上报为准，分类和条目按字符及图片权重估算并校准；不是逐项 tokenizer 实测值。暂无 provider usage 时明确显示估算值。窗口大小可在 `context_windows` 中覆盖。

完整内容浏览限于日志尾部可读取的最近两次请求；历史趋势展示最近 600 步，统计累计覆盖全部步骤。每类预览最多 400 项，单条内容最多 32,000 字符，活动明细最多 500 条，界面标明截断。ZCode 未提供的独立 Prune 事件显示为不可用，不制造事件数据。

- **会话上下文**：Context Stats（轮次/步数/技能加载/回答 + Inject/Compact/Prune 计数）、Token/耗时统计、**Current Context**（七类构成堆叠条：系统提示词/工具定义/用户消息/注入内容/技能注入/模型消息/工具结果，按 provider 实报 tokens 校准）、**Context Browser**（分类展开 + DNA 平铺模式）、**Context Trend**（步级堆叠柱 + 耗时折线 + 错误标记 + 点击下钻）、Context Events（压缩/超限/切模型/出错/取消/子代理）
- **Agent 家族**：主会话 + 子代理（parent_id 关联）的上下文占用（Agents/Running/Work items/Messages 汇总）
- 明/暗双主题、明/暗图标

### 数据来源（全部本机只读，洞察部分零联网）

- Coding Plan：`GET https://open.bigmodel.cn/api/monitor/usage/quota/limit`，鉴权用 API Key（用户配置）或网页登录令牌
- 免费套餐：`GET https://zcode.z.ai/api/v1/zcode-plan/billing/balance?app_version=…&device_mid=…`，令牌由 `~/.zcode/v2/credentials.json` 就地解密（AES-256-GCM）
- 上下文洞察：只读查询 `~/.zcode/cli/db/db.sqlite`（session / turn_usage / model_usage / tool_usage / part）与 `~/.zcode/cli/rollout/model-io-sess_*.jsonl` 尾部（仅末尾 ≤24MB，按需解析最新 2 次请求）

> 用量接口为内部接口，官方改版可能失效。洞察数据结构随 ZCode 版本演进，出现字段变化时会自动降级为部分展示。

## 排错

- **更新或重装插件后面板报 "MCP App connection is unavailable"**：旧任务保留旧的能力目录，请**新建任务**再打开面板
- Coding Plan 显示"未配置 API Key"：在面板 ⚙ 设置里填入 bigmodel.cn 的 API Key，或在 ZCode 内嵌浏览器登录 bigmodel.cn
- 速率/走势显示"采样中…"：历史样本需积累 5～10 分钟
- 洞察"未找到本地会话数据库"：本机没装 ZCode 或从未运行过会话
- Live 构成"没有可解析的 model-io 记录"：会话过旧或 rollout 日志被清理；Trend/Token 统计仍可用
- 模型窗口不准：`~/.glm-usage/config.json` 加 `context_windows: { "模型id": tokens }`
